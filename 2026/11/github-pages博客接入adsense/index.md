# GitHub Pages 博客接入 AdSense：广告代码、ads.txt 与审核前检查清单

博客能正常打开，不代表已经具备展示广告的条件。AdSense 开户、连接站点、站点审核和广告位设置是不同步骤。本教程针对自有域名的静态博客，说明每一步该验证什么，不承诺审核通过或收入。

> 适用范围：能修改站点公共 HTML 模板和发布根目录文件的博客。文中编号均为占位示例，不能原样上线。资料核对日期为 2026 年 11 月 18 日；后台界面以 Google 当前实际页面为准。本文未完成真实广告账号端到端投放测试，不包含任何实测收益。

## 1. 先确认托管用途，而不是先粘代码

GitHub Pages 官方限制说明：它不是用于运行在线业务、电商，或以商业交易、商业 SaaS 为主要目的的网站的免费主机。不要把“技术上能加载广告脚本”理解为所有商业用途都获允许。

个人原创博客是否适合继续使用现有托管，应结合实际用途与服务条款评估；若计划发展成主要依靠商业经营的站点，应另行评估合适的托管。不要在 Pages 上收集密码、支付卡等敏感交易信息。

## 2. 区分三个编号

| 编号 | 用途 | 示例（占位） |
| --- | --- | --- |
| GA4 衡量 ID | 访问统计，不负责展示广告 | `G-XXXXXXXXXX` |
| AdSense 发布商 ID | 识别广告发布者；脚本中带 `ca-` 前缀 | `pub-0000000000000000` |
| 广告单元 ID | 识别具体的手动广告位 | `0000000000` |

不能把 GA4 的 `G-…` 编号放进 AdSense 脚本。广告代码和发布商编号应从自己的 AdSense 后台复制，不要使用教程作者或其他网站的编号。

## 3. 连接站点与审核

在 AdSense 中添加自己的站点，并按后台实际提供的方法验证控制权。某些表单要求使用不带 `www` 的主域名；按照实际校验提示填写，不必为此更改网站的 HTTPS 或强制跳转设置。

账号创建成功不等于站点审核通过。应分别检查收款资料、站点连接和审核状态；补齐当前要求的事项后，再按后台提示申请审核，不用页面出现一个空白广告框来判断是否获批。

## 4. 手动广告位代码放在哪里

下面示例只适用于自己创建的手动展示广告单元。自动广告使用后台提供的设置，不需要照抄同一套手动广告位代码。若只是验证站点，优先按后台提供的验证方式操作。

全站公共模板的 `<head>` 内加载一次：

```html
<!-- 两处发布商编号必须替换为自己的真实编号 -->
<script async
  src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-0000000000000000"
  crossorigin="anonymous"></script>
```

在文章模板中希望展示广告的位置，例如正文结束后，放置广告单元：

```html
<ins class="adsbygoogle"
     style="display:block"
     data-ad-client="ca-pub-0000000000000000"
     data-ad-slot="0000000000"
     data-ad-format="auto"
     data-full-width-responsive="true"></ins>
<script>
  (window.adsbygoogle = window.adsbygoogle || []).push({});
</script>
```

这些是占位模板，不是真实可投放账号。两处 `ca-pub-…` 要一致，`data-ad-slot` 则必须来自对应的广告单元。先查看主题是否已经加载 AdSense，避免在公共模板与文章组件里重复加载库。

不要直接把脚本粘进可能过滤 HTML 的 Markdown 正文。应使用生成器支持的模板或组件，并预览最终 HTML。广告不应遮挡代码、导航和正文，也不应设计成误导读者点击的下载按钮。

## 5. ads.txt 放在发布根目录

`ads.txt` 用来声明哪些卖方被授权销售你的广告资源，不是广告加载脚本，也不能替代站点审核。Google 官方说明它并非统一强制要求，但强烈建议使用；具体操作还应遵循后台当前提示。

从自己的后台复制记录。示例格式如下，里面的发布商 ID 仍是占位符：

```text
google.com, pub-0000000000000000, DIRECT, f08c47fec0942fa0
```

注意这里是 `pub-…`，不是 `ca-pub-…`。将文件放到静态生成器会原样复制至发布根目录的位置，构建后检查产物里是否真的包含 `ads.txt`，而不只检查源码目录。

发布后，用浏览器打开自己域名的 `/ads.txt`，也可执行只读检查。下面的域名是示例，必须替换：

```bash
curl -iL https://example.com/ads.txt
```

检查最终返回内容确实为纯文本记录，而不是 404 页面、首页 HTML、登录页或验证码。若裸域与 `www` 有跳转，也应检查主域名入口最终可达并返回正确文件。Google 后台更新状态可能有延迟，不要因此反复改发布商编号。

## 6. 审核和上线前检查

- 站点有完整、可访问的原创内容与正常导航，没有只放标题的空页面。
- 隐私政策准确说明实际使用的广告、统计和相关数据处理，而不是复制不符合本站情况的模板。
- 若向欧洲经济区（EEA）、英国或瑞士用户投放个性化广告，必须使用经过 Google 认证、且集成 IAB 透明度与同意框架（TCF）的同意管理平台（CMP），不能只加一个普通的 Cookie 提示框。认证不代表已全面满足适用隐私法律，发布者仍需核对实际数据处理与法律义务；中文内容不代表只有中国用户。详见 [Google 官方 CMP 要求](https://support.google.com/adsense/answer/13554116?hl=en)。
- 收款国家、主体及真实身份资料由申请人确认，不因浏览器预填而直接接受。
- 不自行点击广告、不请朋友帮忙点击、不购买虚假流量，也不自动刷新刷展示。
- 手机和桌面均检查布局、加载和控制台错误，不让广告盖住主要内容。

## 7. 空白广告与回滚

广告没有显示时，先确认账号和站点是否仍待审核，再检查发布商和广告单元编号、脚本请求、浏览器扩展、同意状态与布局空间。广告库存、政策限制等也可能影响展示；一次打开没看到广告，不足以证明代码错误。

若刚接入就出现布局或性能问题，回滚本次广告模板改动并重新构建，确认正文恢复正常；不要同时改统计、主题和其他配置。需停用投放时，应核对后台对应的广告设置。广告代码回滚不等于注销账号，也不能替代隐私和合规维护。
